Идея

Айырмасы: жұмысты кім бастайды

Агент тәулік бойы Jira-ны сканерлеп, өзі тапсырма табады. Кезекшіге басқа нәрсе керек: «мынау фичаны қазір тексеруім керек». Skill дәл осыны жабады.

Агент

cron бойынша, өзі табады, өзі шешеді. Күтуге тура келеді.

Skill

сұрау бойынша, дәл сол процедура, дәл сол gate-тер. Қазір.

Ортақ

coverage, oracle, test-data, evidence — бір код, екі кіру нүктесі.

Мүмкіндік 01

Спекадан тест-кейс шығару

>«DV-5877-ге тест-кейс жаз»
01Талаптарды жинайды — Jira, Confluence, балалық және қатар беттер, бар кейс парағы
02Фактіні тексереді — API probe, backend DTO/enum/валидация
03Кейстерді жобалайды — happy path, негатив, шекара, RBAC/IDOR, күй ауысуы, регресс
04Код валидациялап жариялайды — әр талап кейспен жабылды ма, сілтемелер шынайы ма
Нәтиже: Confluence-те трассировка кестесімен жарияланған кейс парағы + PM-ге сұрақтар тізімі.
Тоқтайды: спекада frozen белгісі жоқ · екі үміткер парақ табылды · спека мен факт қайшы.

Мүмкіндік 02

Кейстен Playwright автотест

>«бекітілген кейстерге API тест жаз»
01Барды қайта қолданады — Page Object, фикстура, API клиент; селектор дубльдемейді
02Күтілетінді спекадан алады — БД-дан емес; volatile id API арқылы
03Oracle талабын орындайды — статустан бөлек схема және бизнес-инвариант
04Gate-тен өткізеді — coverage, test-quality, independence, oracle
Нәтиже: feature branch + Draft MR, ішінде @DV/@TC маркерленген, gate өткен тесттер.
Жасамайды: мерж · scope бұлыңғыр болса жазуды бастамайды · mobile scope-ты web-пен жаппайды.

Мүмкіндік 03 · кезекшінің негізгі жұмысы

Препродта тексеру және QA жабу

>«DV-5877-ні препродта тексер, жабуға бола ма»
01Scope — Jira-дан: API, UI немесе mobile handoff
02Орта дайындығы — UI artifact, auth boundary, төрт рөл аккаунты
03Арзан аудиттер — құласа қымбат прогон мүлде басталмайды
04Прогон және evidence — run, commit SHA, парақ нұсқасы, TTL 120 мин
Нәтиже: тоғыз шарт бойынша нақты жауап — COMPLETED немесе PARTIAL, себебімен.
Жаба алмайды: бір retry-pass болса · evidence ескірсе · skipped>0 болса · mobile scope қалса.

Мүмкіндік 04

Тест құлады: баг па, тест пе?

>«бұл тест құлады, себебін тап»
Қатаң ереже: продукт спеканы бұзып тұрса, тестті «жасыл болсын» деп түзетпейді. Grounding дәлелі болмаса, STALE_TEST деп белгілеуге тыйым.

Мүмкіндік 05

Jira баг — контракт бойынша

>«баг аш»

Қолмен жазылған description жоқ: баг renderer арқылы жасалады, құрамы әрқашан толық.

  • Дубль тексерісіStory-дың балалық issue-лары арасынан
  • Қайталанатын қадамдарКемінде екі қадам, нақты object ID, көшіруге дайын curl немесе Playwright командасы
  • Күтілетін + дереккөзСпека/контракт сілтемесі міндетті
  • Нақты код аймағыRead-only grounding-пен табылған файл/метод
  • EvidenceТест spec + кемінде бір тірі Allure/pipeline сілтемесі

Мүмкіндік 07

Дизайнмен сәйкестік және орта диагностикасы

>«дизайнмен салыстыр» · «препрод сынды ма»

Figma сверкасы

Мәтін салыстыруы бірінші — i18n, copy, батырма атауы, реттілік суретсіз табылады. Сосын құрылымдық визуал. Pixel-perfect емес.

Орта диагностикасы

Төрт тәуелсіз тексеріс: UI artifact, API auth, төрт рөл аккаунты, deploy метадеректері. Категория, иесі, әрекет береді.

Шешім дисциплинасы: спека мен дизайн қайшы болса — UNKNOWN, эскалация. «Маған ұнамайды» баг емес: тексерілетін oracle жоқ.

Мүмкіндік 08

Кезекшілік есебі

>«кезекшілік есебін дайында»

Әдепкі режим — жібермеу. Алдымен мәтінді көрсетеді, растағаннан кейін ғана жібереді.

  • Қай DV қаралды, қай статуста
  • Қай gate өтті, қай жерде PARTIAL
  • Evidence және Allure сілтемесі
  • Ашылған және жабылған багтар
  • Не тексерілмеді және негеБұл жол міндетті — есептің ең маңызды бөлігі
