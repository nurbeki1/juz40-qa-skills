# Орта режимдері: не бар, сол бойынша жұмыс

Skill екі репоға сүйенеді, бірақ олардың **болуын пайдаланушыдан сұрамайды** —
`scripts/preflight.sh` өзі тауып, режимді шешеді. Бұл файл режимдердің нақты
шекарасын сипаттайды.

| Репо | Не үшін | Жоқ болса |
|---|---|---|
| `juz40-aqa-agent007` (орkестратор) | барлық детерминды gate, renderer, evidence | gate жоқ → `TESTS_ONLY` |
| `juz40-aqa-repo` (Playwright) | тесттердің өзі, `ground.sh` | тест жазу/жүгірту жоқ |

## MODE: FULL

Барлық 11 процедура ашық. Ештеңе шектелмейді.

## MODE: SETUP

Орkестратор табылды, бірақ дайын емес. Preflight нақты команда береді:

```bash
npm --prefix "<ORCH>" ci
cp "<ORCH>/.env.example" "<ORCH>/.env"     # сосын ӨЗ токендерін қой
npm --prefix "<ORCH>" run auth:check -- --probe
```

`.env`-ті **пайдаланушы өзі** толтырады (токенді чатқа сұрауға тыйым —
[auth.md](auth.md)). Толтырғаннан кейін preflight-ты қайта іске қос.

## MODE: TESTS_ONLY — ең маңызды шекара

Орkестратор репосы жоқ. Жұмысты мүлде тоқтатпайды, бірақ **шындықты жасырмайды**.

| Қолжетімді | Қолжетімсіз |
|---|---|
| Grounding: API probe, продукт коды, read-only DB | `coverage` / `test-quality` / `oracle` / `independence` аудиті |
| Спека оқу (Jira/Confluence MCP немесе токен) | Confluence-ке кейс парағын жариялау (renderer) |
| Тест-кейс жобалау (мәтін/кесте күйінде) | Jira баг жасау (`bug:report` renderer) |
| Playwright тест жазу және жүгірту | Evidence верификациясы, TTL, run/commit байланысы |
| Құлауды триаж жасау (талдау) | `readiness:diagnose` орта диагностикасы |
| Figma сверкасы (MCP болса) | QA жабу шешімі, дейлик есеп жіберу |

**Қатаң:** бұл режимде `COMPLETED`, «толық тексерілді», «QA жабуға болады»
деген қорытынды шығаруға тыйым. Дұрыс қорытынды: «мынау жазылды/жүгірілді,
gate өтпеді, себебі орkестратор қолжетімсіз».

Толық режимге өту — бір клон:

```bash
git clone <juz40-aqa-agent007 URL>
bash "$CLAUDE_PLUGIN_ROOT/scripts/preflight.sh"
```

## MODE: BOOTSTRAP

Ештеңе табылмады (жаңа қызметкер, жаңа машина). Preflight клондау нұсқауын
береді. Репо URL-дерін skill білмейді — ол команда ішіндегі ақпарат, сондықтан
пайдаланушыдан немесе команда лидінен сұрауды ұсынады.

## Неге gate-тер plugin ішіне салынбады

Gate-тер — 60-тан астам TypeScript модулі: Jira/Confluence клиенттері, AST
анализ, evidence схемалары, renderer-лер. Оларды plugin-ге көшіру екі салдарға
апарады: (1) екі көшірме бір-бірінен ажырап, skill ескірген gate-пен тексере
бастайды; (2) сапа табалдырығы екі жерде анықталады — бұл «gate-ті жеңілдетуге
тыйым» ережесін мағынасыз қылады. Сондықтан бір дереккөз: орkестратор репосы.

Болашақ жақсарту: орkестраторды ішкі npm пакет ретінде шығару — сонда
`npx @juz40/aqa-gates coverage DV-XXXX` жұмыс істейді де, клон қажет болмайды.
