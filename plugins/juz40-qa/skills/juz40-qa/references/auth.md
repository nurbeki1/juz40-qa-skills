# Авторизация: кім, қайдан, кімнің атынан

Агент headless жүреді — барлық токен `.env`-те сервис-аккаунт ретінде берілген.
Skill-ді **адам** іске қосады, сондықтан авторизация үш түрлі жолмен болады.
Таңдау міндетті: кім жазғаны Jira-да көрінеді.

## Үш нұсқа

| Нұсқа | Қалай | Жазба кімнің атынан | Қашан |
|---|---|---|---|
| **A. Ортақ сервис `.env`** | Агент репосының `.env`-і | `agent007` | Тек **оқу** үшін. Жазуға ұсынылмайды |
| **B. Жеке токен** | Әркімнің өз `.env`-і | **өз атынан** | Jira баг, Confluence жариялау, GitLab MR |
| **C. MCP коннектор** | `/mcp` → браузерде бір рет кіру | өз атынан, токен файлда жоқ | Оқу (Jira/Confluence/Figma). CI-да жұмыс етпейді |

**Ұсынылатын гибрид:** оқу — C (немесе A), жазу — B.

## Жетіспесе не істеу керек (нақты нұсқау)

`auth:check` шығысы әр жол үшін `→` нұсқауын береді. Қысқаша:

| Жетіспейді | Шешімі |
|---|---|
| Jira/Confluence | `/mcp` → Atlassian коннекторы; **немесе** id.atlassian.com → Security → API tokens → `.env`: `JIRA_EMAIL`, `JIRA_API_TOKEN` |
| GitLab | GitLab → Preferences → Access tokens (scope `api` + `write_repository`) → `.env`: `GITLAB_TOKEN` |
| Figma | Figma → Settings → Security → PAT (scope «File content: read») → `.env`: `FIGMA_TOKEN`; немесе Figma MCP |
| Препрод аккаунттары | `npm run readiness:diagnose` — рөл credential жұптарын тексереді |
| Read-only DB | `AGENT_DB_URL` (жоқ болса grounding қадамы скипается, бұл қалыпты) |
| Telegram | Жоқ болса есеп `--dry` режимде қалады |

## Қатаң шектеулер

- Браузердегі интерактив логинді **агент жасай алмайды**. Адамға нақты команда
  немесе қадам бер, өзі кіргенше ТОҚТА.
- Пайдаланушыдан токенді чатқа жазуды **сұрама**. Ол `.env`-ке өзі қояды.
- Токен мәнін экранға баспа (`auth:check` та баспайды — тек ұзындығын).
- Жазуды MCP арқылы жасама: Confluence/Jira жазбасы міндетті түрде Node
  renderer-інен өтеді (`write-testcases`, `bug:report`) — валидация сол жерде.
- Токен жарамсыз болса (`--probe` 401 береді) — жаңасын жасауды сұра,
  басқа дереккөзге «ауысып» кетпе.
