# Құлаған тестті триаж жасау

Бұл — бүкіл процестің **ядросы**. Қателессең: шынайы баг жасырылады немесе
бос баг ашылады. Канон: `agent/prompts/triage.md`, `agent/skills/self-heal.md`.

## ⛔ Басты guardrail

**Продукт спеканы бұзып тұрса, тестті «жасыл болсын» деп ЕШҚАШАН түзетпе.**
Күтілетін мәнді продуктің қате мінезіне бейімдеу = багты жасыру. Алдымен
СЕБЕП, сосын әрекет. Тестті өзгертуге тек тестте қате екені **дәлелденгенде**
болады.

## Кіріс

тест аты/файлы, қате мәтіні (assertion diff), stack, артефакттар (screenshot,
trace, video, network), retry саны мен нәтижесі, ағымдағы спека, байланысты MR.

## Процедура

### 1. Grounding (вердикттен бұрын)

```bash
cd "$TEST_REPO_PATH/playwright"
scripts/ground.sh <METHOD> <path> [role]
scripts/ground-db.sh "select ..."    # керек болса
```

Толық: [grounding.md](grounding.md). UI болса + [figma-check.md](figma-check.md).

### 2. Үш салыстыру вердиктті шешеді

| Салыстыру | Вердикт |
|---|---|
| ФАКТ ≠ СПЕКА | **PRODUCT_BUG** |
| ТЕСТ ≠ СПЕКА, ФАКТ = СПЕКА | **STALE_TEST** / **TEST_ERROR** |
| Өзгеріссіз retry-да өтті | **FLAKY** |
| Спека жоқ / фича deploy емес / қайшылық | **UNKNOWN** |

### 3. Кластар мен әрекет

1. **PRODUCT_BUG** — deployed факт бекітілген спека/контрактқа қарсы.
   → Jira баг (Story астына subtask) [bug-report.md](bug-report.md).
   **Тестті түртпе** — қызыл тест регрессия дәлелі.
2. **STALE_TEST** — продукт спека бойынша заңды өзгерді, тест қалып қалды.
   → self-heal (төменде).
3. **TEST_ERROR** — тест қате допущение жасады (продукт әрқашан осылай болған).
   → тестегі допущениені түзет.
4. **FLAKY** — тұрақсыз (тайминг/желі/анимация), retry-да өтті.
   → баг емес; тұрақтандыр. **Жасыл completion саналмайды.**
5. **UNKNOWN** — дерек жетпейді немесе дереккөздер қайшы.
   → адамға эскалация. Болжамау, тестті өзгертпеу.

### 4. Self-heal (тек STALE_TEST / TEST_ERROR)

1. Grounding фактісі қолда болуы керек.
2. **Минимал түзету** — тек ескіргенін (селектор/өріс/мән/endpoint). Тестті
   қайта жазба, көрші кейстерді түртпе, assertion-ды «өтсін» деп әлсіретпе.
3. **Жасылмен дәлелде**: `--workers=1` сол тестті жүгірт — ол **іс бойынша**
   өтуі керек. Өту үшін тексерісті алып тастауға тура келсе — **ТОҚТА**,
   бұл heal емес (мүмкін PRODUCT_BUG).
4. Commit: `test(pw): self-heal <spec> — <не ескірді> → <спека бойынша қалай> (<DV/TC>)`,
   денесінде grounding сілтемесі.
5. MR `self-heal` префиксімен: болды → болды → неге. **Өзіңше мержемейсің.**
6. Дашбордқа оқиға:
   ```bash
   npm --prefix "$AGENT_ORCHESTRATOR_PATH" run event -- triage \
     --tc "TC-3 maxScore" --verdict STALE_TEST --note "self-heal: қысқаша"
   ```

### Self-heal НЕ істемейді

- Продуктті түзетпейді, оның репосына жазбайды (тек grounding үшін оқу).
- Көптеп «жасылдамайды»: құлау көп болса, алдымен ортақ себепті түсін
  (регресс болуы мүмкін) — біртіндеп соқыр патч салмайды.
- Қызылды жою үшін тестті өшірмейді/скиптемейді. Саналы skip — тек себебі
  жазылған, уақытша және ашық белгіленген жағдайда.

## Flaky тарихы

Story бойынша соңғы 20 verification run сақталады; dashboard clean streak,
flaky және failed санын көрсетеді. UI quarantine жарамды болуы үшін: `owner`,
кемінде 20 таңбалы `reason`, болашақтағы `expiresAt`. Мерзімі өткен rule
coverage аудитін құлатады.
